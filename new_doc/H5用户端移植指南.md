# H5 用户端移植指南

这份文档给接手移植的 AI 或工程师使用。目标是把当前 demo 的用户端能力移植到已有 H5 移动端项目中。

## 目标效果

H5 页面连接 Python 后端 WebSocket，发送文本后接收后端推送的 TTS 音频流。页面一边播放音频，一边把视频从“待机视频”切到“说话视频”；音频播放完后，再平滑切回“待机视频”。

整体链路：

```text
H5/JavaScript
  -> WebSocket 发送文本
Python TTS 后端
  -> 调用豆包 TTS
  -> WebSocket 推送 pcm_s16le 音频二进制流
H5/JavaScript
  -> Web Audio 播放音频流
  -> 控制说话/待机视频切换
```

- Node/H5 demo 用户端：[h5_node_client.mjs](/Users/bytedance/study/AI电商/doubao/h5_node_client.mjs)

移植 H5 时，重点看 `h5_node_client.mjs` 里的 HTML、CSS、浏览器端 `<script>` 代码。Node 的 HTTP 服务部分只是为了本地 demo 提供页面和视频文件，不需要移植到移动端项目。

## 要移植的内容

从 `h5_node_client.mjs` 中移植这些浏览器端能力：

- 两个 video 层：
  - `idleVideo`：待机视频，循环播放，静音。
  - `talkVideo`：说话视频，循环播放，静音，用 opacity 叠在待机视频上。
- WebSocket 连接 Python 后端。
- 文本发送逻辑。
- WebSocket JSON 消息处理。
- WebSocket 二进制音频流处理。
- Web Audio PCM 播放逻辑。
- 音频播放时切到说话视频，播放结束后切回待机视频。
- 移动端音频解锁逻辑。

不要移植这些内容：

- Node `createServer` 静态服务代码。
- `sendVideo()`、Range 请求处理代码。
- Python TTS 调用逻辑。
- `.env` 读取、豆包 APP ID、Access Key 等后端凭证。

## 后端 WebSocket 协议

默认连接地址：

```text
ws://127.0.0.1:8876/tts
```

手机调试时要换成电脑局域网 IP：

```text
ws://电脑IP:8876/tts
```

生产环境建议使用 HTTPS/WSS：

```text
wss://你的域名/tts
```

### H5 发给 Python

发送文本：

```json
{
  "type": "speak",
  "text": "欢迎来到直播间，今天给大家介绍一件臻品。"
}
```

### Python 发给 H5

连接成功：

```json
{
  "type": "ready",
  "server": "python-tts-stream",
  "audio_format": "pcm_s16le"
}
```

音频开始：

```json
{
  "type": "audio_start",
  "id": "request-id",
  "text": "播报文本",
  "audio_format": "pcm_s16le",
  "sample_rate": 24000,
  "channels": 1
}
```

音频数据：

```text
WebSocket binary frame
格式：pcm_s16le
采样率：24000
声道：1
字节序：little-endian
```

音频结束：

```json
{
  "type": "audio_end",
  "id": "request-id",
  "elapsed_ms": 1234,
  "sample_rate": 24000,
  "channels": 1,
  "audio_format": "pcm_s16le",
  "audio_bytes": 123456,
  "chunk_count": 10
}
```

错误：

```json
{
  "type": "error",
  "id": "request-id",
  "error": "错误信息"
}
```

## PCM 播放核心逻辑

后端推送的是 `pcm_s16le`，浏览器不能直接当作 mp3/wav 播放，要用 Web Audio 转成 `AudioBuffer`。

核心转换逻辑：

```js
function schedulePcm(arrayBuffer) {
  const frameCount = Math.floor(arrayBuffer.byteLength / 2);
  const view = new DataView(arrayBuffer);
  const samples = new Float32Array(frameCount);

  for (let index = 0; index < frameCount; index += 1) {
    const value = view.getInt16(index * 2, true);
    samples[index] = Math.max(-1, Math.min(1, value / 32768));
  }

  const buffer = state.audioContext.createBuffer(1, frameCount, state.sampleRate);
  buffer.copyToChannel(samples, 0);

  const source = state.audioContext.createBufferSource();
  source.buffer = buffer;
  source.connect(state.audioContext.destination);

  const startAt = Math.max(
    state.audioContext.currentTime + 0.03,
    state.nextStartTime || state.audioContext.currentTime + 0.08
  );

  state.nextStartTime = startAt + buffer.duration;
  source.start(startAt);
}
```

注意：不要把每个音频 chunk 单独创建 `<audio>` 播放，容易断裂、延迟大、不能精确排队。这里使用 `nextStartTime` 把 PCM chunk 串起来。

## 移动端音频限制

移动端浏览器通常不允许无用户手势自动播放有声内容。必须保留一个“启用声音”按钮，用户第一次进入页面时点击一次：

```js
async function unlockAudio() {
  await ensureAudioContext();
  if (state.audioContext && state.audioContext.state === "running") {
    unlockButton.disabled = true;
    flushPendingPcm();
  }
}
```

如果用户没有提前点击，收到音频流时可以先缓存到 `pendingPcmChunks`，等用户点击“启用声音”后再播放。

## WebSocket URL 配置

建议在目标项目里把后端地址做成配置：

```js
const TTS_WS_URL = import.meta.env?.VITE_TTS_WS_URL || "ws://127.0.0.1:8876/tts";
```

如果不是 Vite，就用项目自己的环境变量方案。不要把豆包 APP ID、Access Key 放进 H5。

## 框架移植建议

### 原生 H5

页面加载时：

```js
forceMuted(idleVideo);
forceMuted(talkVideo);
ensureIdlePlayback();
connectBackend();
```

页面卸载时：

```js
stopPlayback();
state.socket?.close();
```

### Vue

在 `onMounted()` 中初始化视频和 WebSocket，在 `onBeforeUnmount()` 中停止播放并关闭 WebSocket。

### React

在 `useEffect(() => { ...; return cleanup; }, [])` 中初始化和清理。DOM 节点建议用 `useRef`，不要反复用 `document.getElementById`。

### uni-app / WebView

如果运行在普通 H5 WebView，优先使用浏览器原生 `WebSocket` 和 `AudioContext`。如果目标容器限制 Web Audio，需要改成后端推送 wav/mp3 分片或整段音频 URL。

## 移植步骤

1. 把待机视频和说话视频放进目标项目静态资源目录。
2. 在页面中加入两个 video 层，并确保都 `muted playsinline preload="auto"`。
3. 加入 `stage.is-speaking` 的 opacity 切换样式。
4. 把 `h5_node_client.mjs` 里的浏览器端 JS 移到目标页面。
5. 把 `buildWsUrl()` 改成目标项目的后端 WebSocket 地址。
6. 确认 `socket.binaryType = "arraybuffer"`。
7. 确认收到 JSON 时走 `handleJsonMessage()`，收到二进制时走 `handleAudioChunk()`。
8. 点击“启用声音”后检查 `AudioContext.state === "running"`。
9. 点击“发送并播报”，确认 `audio_start` 后视频切到说话。
10. 确认收到 `audio_end` 后视频能回到待机。

## 验收标准

- 页面加载后待机视频循环播放。
- WebSocket 状态显示已连接。
- 点击发送后，Python 后端收到文本。
- H5 能收到二进制 PCM 音频流，`已收音频` 数字增长。
- 收到音频流后切到说话视频。
- 音频播放结束后回到待机视频。
- 视频始终静音，只播放 TTS 音频。
- 移动端 Safari/Chrome 中首次播放前有“启用声音”入口。
- 控制台没有 WebSocket、AudioContext、视频加载相关错误。
